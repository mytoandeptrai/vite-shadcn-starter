## Directory Purposes

**`src/apis/`:**
- Purpose: backend communication boundary
- Key files: `src/apis/http-instance.ts`, `src/apis/auth/*`, `src/apis/transactions/*`

**`src/integrations/`:**
- Purpose: initialize and provide third-party libraries across app
- Key files: `src/integrations/i18n/root-provider.tsx`, `src/integrations/tanstack-query/root-provider.tsx`, `src/integrations/auth/auth-provider.tsx`

**`src/routes/`:**
- Purpose: route definitions used by TanStack Router
- Key files: `src/routes/__root.tsx`, `src/routes/(auth)/layout.tsx`, `src/routes/(private)/layout.tsx`, `src/routes/404.tsx`

**`src/modules/`:**
- Purpose: feature-module implementation (UI + local logic per feature)
- Contains: `dashboard/`, `transactions/`, `transaction-detail/`, demo modules

## Key File Locations

**Entry Points:**
- `src/main.tsx` - app bootstrap + provider composition
- `index.html` - HTML shell with mount element (`#app`)

**Configuration:**
- `vite.config.ts` - dev/build/test config
- `tsconfig.json` - TS strict mode + alias `@/*`
- `biome.json` - formatting/lint rules
- `.env` / `.env.example` - Vite environment variables (names only in code via `src/constant/base.const.ts`)

**Testing:**
- `src/test/setup.ts` - Vitest setup file (referenced from `vite.config.ts`)

## Naming Conventions

**Files:**
- Route files follow TanStack Router naming patterns including groups like `(auth)` / `(private)` (see `src/routes/`)
- UI components commonly use kebab-case directories with TSX files inside (see `src/components/shared/`)

**Directories:**
- Feature modules in `src/modules/<feature>/`
- API domains in `src/apis/<domain>/`

## Where to Add New Code

**New API domain wrapper:**
- Requests/queries/types: `src/apis/<domain>/`

**New feature page:**
- Route: `src/routes/<path>.tsx`
- Feature UI: `src/modules/<feature>/`

**New shared UI primitive:**
- `src/components/ui/` (shadcn-style)

**New cross-cutting integration/provider:**
- `src/integrations/<name>/`

## Special Directories

**`src/routeTree.gen.ts`:**
- Purpose: generated routing tree for TanStack Router
- Source: generated by `@tanstack/router-plugin` (Vite plugin)
- Committed: yes (present in repo); avoid manual edits

# Codebase Structure

**Analysis Date:** 2026-04-20

## Directory Layout

```
[project-root]/
├── index.html                 # HTML entry (mounts #app)
├── vite.config.ts             # Vite + TanStack Router plugin + Vitest config
├── tsconfig.json              # TypeScript config + @/* path alias
├── package.json               # Scripts + dependencies
├── public/                    # Static assets served as-is
├── src/                       # Application source (React SPA)
│   ├── main.tsx               # React entry; provider stack; router creation
│   ├── routeTree.gen.ts       # Generated route tree (do not edit)
│   ├── routes/                # File-based routing (TanStack Router)
│   ├── modules/               # Feature modules (containers/components/hooks)
│   ├── apis/                  # API clients + react-query hooks per domain
│   ├── integrations/          # App-wide providers (auth/i18n/query/theme/etc.)
│   ├── stores/                # Zustand client-state stores
│   ├── components/            # Shared UI (layouts, ui primitives, shared)
│   ├── utils/                 # Generic utilities (helpers, formatting, etc.)
│   ├── constant/              # App constants (routes, enums, site config)
│   ├── types/                 # Shared TypeScript types
│   ├── hooks/                 # Cross-feature reusable hooks
│   ├── contexts/              # React contexts (non-integration)
│   ├── styles/                # Style assets (if separated from styles.css)
│   ├── styles.css             # Global styles entry
│   ├── assets/                # Bundled assets imported by code
│   ├── data/                  # Local data/fixtures (project-specific)
│   ├── workers/               # Web workers (if used)
│   └── test/                  # Test setup + helpers
├── .tanstack/                 # TanStack Router tooling artifacts/config
├── .storybook/                # Storybook config
├── docs/                      # Project documentation (repo-local)
└── docker/                    # Docker-related assets
```

## Directory Purposes

**`src/main.tsx`:**
- Purpose: SPA bootstrap and provider composition.
- Key responsibilities: create router (`@tanstack/react-router`), mount providers (`src/integrations/*`), set up error boundary and suspense.

**`src/routes/`:**
- Purpose: URL routing layer (file-based TanStack Router).
- Contains:
  - Root route: `src/routes/__root.tsx`
  - Layout routes: `src/routes/(private)/layout.tsx`, `src/routes/(auth)/layout.tsx`
  - Leaf routes: e.g. `src/routes/(private)/transactions/index.tsx`, `src/routes/(private)/transactions/$transactionId.tsx`
- Notes: `src/routeTree.gen.ts` is generated from this directory; treat it as build output.

**`src/modules/`:**
- Purpose: Feature implementation layer (“module-based architecture”).
- Contains:
  - `containers/`: page-level composition (often exported and used directly by routes)
  - `hooks/`: orchestration hooks that combine URL state + API calls + UI callbacks
  - `components/`: feature-scoped UI components
- Example feature:
  - `src/modules/transactions/containers/transaction-container/transaction-container.tsx`
  - `src/modules/transactions/hooks/use-payments-container.ts`

**`src/apis/`:**
- Purpose: Data access + domain query hooks.
- Contains:
  - HTTP client: `src/apis/http-instance.ts` (+ `src/apis/http-instance.helper.ts`)
  - Domain modules: e.g. `src/apis/transactions/{requests.ts,queries.ts,types.ts,keys.ts}`
- Convention: Prefer consuming query hooks (e.g. `useGetTransactionList` in `src/apis/transactions/queries.ts`) from module hooks/containers.

**`src/integrations/`:**
- Purpose: Cross-cutting providers and infrastructure bindings.
- Key files:
  - `src/integrations/infra-providers.tsx` (composes Theme + Dialog + Auth providers)
  - `src/integrations/tanstack-query/root-provider.tsx` (QueryClient + provider)
  - `src/integrations/auth/auth-provider.tsx` (auth context; session awareness)
  - `src/integrations/i18n/*` (i18next configuration and provider)

**`src/stores/`:**
- Purpose: Client-side state via Zustand.
- Key files:
  - `src/stores/use-session-store.ts` (token storage; persisted to localStorage)

**`src/components/`:**
- Purpose: Shared UI building blocks and reusable app scaffolding.
- Notable subareas:
  - Layouts: `src/components/layouts/*` (e.g. `app-header`, `app-sidebar`)
  - Containers: `src/components/containers/*` (e.g. `page-container.tsx`)
  - UI primitives: `src/components/ui/*` (shadcn/radix-based components)

## Key File Locations

**Entry Points:**
- `index.html`: Mount point and script entry.
- `src/main.tsx`: App bootstrap and provider wiring.

**Routing:**
- `src/routes/__root.tsx`: Root shell + SEO + devtools + `<Outlet />`.
- `src/routes/(private)/layout.tsx`: Auth-guarded layout wrapper.
- `src/routes/(auth)/layout.tsx`: Auth-only layout wrapper.
- `src/routeTree.gen.ts`: Generated router tree (do not edit).

**Configuration:**
- `vite.config.ts`: Vite plugins and TanStack Router generation; Vitest settings.
- `tsconfig.json`: Strict TS + `@/*` alias (`"paths": { "@/*": ["./src/*"] }`).
- `biome.json`: Lint/format configuration (project-level).
- `components.json`: shadcn/ui component config (project-level).

**Core Logic:**
- Feature entrypoints: `src/modules/**/index.ts` (barrel exports), e.g. `src/modules/transactions/index.ts`.
- HTTP: `src/apis/http-instance.ts`.
- Session store: `src/stores/use-session-store.ts`.

**Testing:**
- `src/test/setup.ts`: Vitest setup (referenced by `vite.config.ts`).

## Naming Conventions

**Files:**
- Routes: TanStack Router file routes under `src/routes/`:
  - Groups in parentheses: `src/routes/(private)/...`, `src/routes/(auth)/...`
  - Dynamic params: `$paramName` (e.g. `src/routes/(private)/transactions/$transactionId.tsx`)
  - Root route: `src/routes/__root.tsx`
- Modules:
  - `index.ts` barrels at module root (e.g. `src/modules/transactions/index.ts`)
  - Containers often nested by responsibility: `src/modules/<feature>/containers/<name>/<name>.tsx`
  - Hooks named `use-*.ts` (e.g. `src/modules/transactions/hooks/use-payments-container.ts`)

**Directories:**
- Domain groupings are explicit and stable: `routes/`, `modules/`, `apis/`, `integrations/`, `stores/`.

## Where to Add New Code

**New Page/Route:**
- Add route file: `src/routes/<path>.tsx` (use TanStack Router `createFileRoute`).
- Render an exported module container from `src/modules/<feature>/...` rather than embedding feature logic directly in the route.

**New Feature Module:**
- Primary code: `src/modules/<feature>/`
  - Container: `src/modules/<feature>/containers/<container-name>/<container-name>.tsx`
  - Feature hooks: `src/modules/<feature>/hooks/use-<something>.ts`
  - Feature components: `src/modules/<feature>/components/<component-name>/<component-name>.tsx` (or similar)
- Export surface: `src/modules/<feature>/index.ts` for route imports.

**New API Domain:**
- Add under `src/apis/<domain>/`:
  - `requests.ts` for raw HTTP calls (using `src/apis/http-instance.ts`)
  - `types.ts` for request/response types
  - `keys.ts` for react-query keys
  - `queries.ts` for `useQuery` hooks
- Use from module hooks/containers (e.g. pattern in `src/apis/transactions/queries.ts` consumed by `src/modules/transactions/hooks/*`).

**New Shared UI Component:**
- Shared primitive: `src/components/ui/<component>.tsx`
- Shared layout: `src/components/layouts/<layout-name>/...`
- Shared container wrapper: `src/components/containers/<name>.tsx`

**Utilities:**
- Shared helpers: `src/utils/` (keep domain-agnostic)
- App constants: `src/constant/` (routes in `src/constant/route.const.ts`, barrel via `src/constant/index.ts`)

## Special Directories

**`src/routeTree.gen.ts`:**
- Purpose: Generated router tree from TanStack Router tooling.
- Generated: Yes (via `@tanstack/router-plugin/vite` configured in `vite.config.ts`).
- Committed: Yes.

**`.tanstack/`:**
- Purpose: TanStack tooling artifacts/config.
- Generated: Yes (tooling-managed).
- Committed: Yes.
